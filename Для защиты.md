# Работа 2 — краткий гайд для защиты (CVE-2021-43798)

> Старая версия работы на CVE-2021-41773 (Apache) заархивирована в `lab2/archive/`,
> потому что эта CVE уже занята другой группой. Текущая работа — **Grafana, CVE-2021-43798**.

## Что сказать за полминуты

«Я исследовал CVE-2021-43798 — обход каталога (directory traversal, CWE-22) в Grafana
8.0.0-beta1 … 8.3.0. Обработчик статических файлов плагина подставляет имя файла из URL
без очистки «../», поэтому неаутентифицированный запрос вида
`/public/plugins/alertlist/../../…/tmp/lab2-proof.txt` читает файл за пределами каталога
плагина. На локальном Docker-стенде уязвимая 8.3.0 вернула файл (HTTP 200 + маркер),
а исправленная 8.3.1 на тот же запрос ответила HTTP 404. Все шесть проверок прошли».

**Это не взлом хоста:** читается специально подготовленный синтетический файл
`/tmp/lab2-proof.txt` (без секретов), смонтированный в контейнер только для чтения.
Порты опубликованы только на `127.0.0.1`. Реальные конфиги и пароли Grafana не запрашивались.

## Как показать

Из корня проекта:

```bash
docker compose -f lab2/compose.yaml up -d
python3 lab2/demo.py
```

Скрипт запускает `verify.py`: он шлёт одинаковые запросы в оба контейнера
(18083 — уязвимый, 18084 — исправленный), проверяет версию через `/api/health`,
код ответа и содержимое, сохраняет `results.json`. Параметра для чужого адреса нет —
только два фиксированных localhost-порта.

Покажи:

1. **Уязвимый (Grafana 8.3.0, :18083):** обход каталога → HTTP 200 и строка
   `LAB2-CVE-2021-43798-CONTROLLED-FILE` из подготовленного файла.
2. **Исправленный (Grafana 8.3.1, :18084):** тот же запрос → HTTP 404 «Plugin file not found».
3. **Регрессия:** обычный вход `/login` в обеих версиях — HTTP 200 (исправление не сломало работу).
4. `all_passed: true`, 6 из 6 проверок. `200` сам по себе не доказывает — проверяется и содержимое (маркер).

Остановить стенд:

```bash
docker compose -f lab2/compose.yaml down
```

## В чём причина

Первичный дефект — **в коде маршрутизации ресурсов плагина Grafana**: запрошенное имя
файла соединялось с каталогом плагина без нормализации и проверки выхода за его пределы
(не применялась очистка пути + проверка префикса). Последовательности `../` уводили чтение
вверх по файловой системе процесса Grafana. Точкой входа служит штатный встроенный плагин
`alertlist` — сторонние плагины не ставились. Уязвимость **доаутентификационная**.

Исправление в 8.3.1 добавляет очистку и проверку запрошенного пути, поэтому тот же запрос
возвращает отказ. Для точного запроса используется `http.client`, сохраняющий путь как есть;
через curl нужен `--path-as-is`, иначе клиент свернёт `../` до отправки.

## Почему CVSS 7.5 (а не выше)

NVD/GHSA дают **CVSS 3.1 = 7.5 HIGH**, вектор `AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N`:
по сети, без прав и без взаимодействия, высокое влияние на конфиденциальность
(чтение произвольных файлов), без прямого влияния на целостность и доступность.
На практике чтение конфигов Grafana (пароли источников данных, ключи) может вести к
дальнейшей компрометации — это уже цепочка, базовый вектор отражает именно раскрытие данных.

## Ответы на контрольные вопросы

- **Зачем Docker?** Воспроизводимое изолированное окружение; можно удалить учебный сервис,
  не ставя уязвимую версию на хост. Изоляция не абсолютна — здесь дополнительно только loopback.
- **Уязвимость vs эксплойт.** Уязвимость — дефект обработки пути; эксплойт — конкретный
  запрос с `../`, его использующий.
- **Зачем регрессионная проверка?** Запретить всё можно и отключением сервиса; HTTP 200 на
  `/login` подтверждает, что после обновления штатная работа сохранилась.
- **Зачем воспроизводить CVE?** Проверить условия эксплуатации, оценить последствия,
  распознать признаки в журналах, подтвердить исправление.
